# 056 - game_setRoomWaves: the underwater background ripple

_2026-07-15_

Part 3 (final) of the BACKLOG §0 Lua host-API audit. Only the `mirror`/`zx`
per-pixel draw effects remain open there.

## What the original does

`game_setRoomWaves(amp, periode, speed)` -> `Room::setWaves()` ->
`WavyPicture::setWamp/setWperiode/setWspeed`. `WavyPicture::drawOn()` blits the
background **one scanline at a time**, each row shifted horizontally with
wrap-around (a second "pad" blit carries the wrapped remainder):

```cpp
float shift = TimerAgent::agent()->getCycles() * m_speed;
for (int py = 0; py < m_surface->h; ++py) {
    Sint16 shiftX = (Sint16)(0.5 + m_amp * sin(py / m_periode + shift));
    ...blit row py from x=shiftX, plus the wrapped pad...
}
```

`m_amp == 0` short-circuits to a plain blit (its constructor default).

**The Lua wrapper matters** (`level_creation.lua`):

```lua
function setRoomWaves(double_amp, periode, inv_speed)
    game_setRoomWaves(double_amp/2, periode, 1/inv_speed)
end
```

so the ubiquitous `setRoomWaves(5, 10, 5)` is really `(amp 2.5, periode 10,
speed 0.2)`: a +-2.5px ripple, ~63px wavelength, advancing 0.2 rad per 100ms
cycle (= 2 rad/s). **68 of the 81 levels use exactly that**; 2 use amp 0.

## Port

**Params are static.** `setRoomWaves` is only ever called from `models.lua`,
never at runtime - so `levelLoader.ts` captures them into `LevelData.waves`
(`RoomWaves`), no live-engine plumbing needed, and ReplayScene gets them free.
`levelScript.ts`'s `game_setRoomWaves` stays a no-op (it re-runs models.lua).

**Rendering.** New `web/src/scenes/WavyBackground.ts`. Per-scanline shifting with
wrap *is* a one-line fragment shader, so it's one draw call instead of ~555 blits
plus a per-frame texture upload - and Phaser's own Shader docs name this exact
case ("for background or special masking effects, they are extremely effective"):

```glsl
float rowFromTop = (1.0 - outTexCoord.y) * uSize.y;   // outTexCoord is bottom-left origin
float shiftX = floor(0.5 + uAmp * sin(rowFromTop / uPeriode + uPhase));
float u = fract(outTexCoord.x + shiftX / uSize.x);    // fract() = the original's wrap "pad"
gl_FragColor = texture2D(uMainSampler, vec2(u, outTexCoord.y));
```

Two wrinkles handled:
- A Phaser `Shader` samples a **whole texture**, but our background is a frame in
  the level atlas (docs/042) - so the frame is copied once into a standalone
  canvas texture at create (docs/048 guarantees opaque bg frames are untrimmed
  and full-size, so it's a straight 1:1 blit). `game_changeBg` (docs/033)
  re-extracts into the same key.
- Phase uses continuous scene time rather than the original's integer
  `getCycles()`: same wave at the same rate (`(t/CYCLE_MS)*speed`), just smooth
  at 60fps instead of stepping 10x/sec (the original's draw loop runs at that
  rate anyway).

**Fallbacks:** `amp == 0` (WavyPicture's own short-circuit) or a non-WebGL
renderer -> a plain `Image`, so the background always renders.

## Verification (real browser, sandbox)

- `airplane`: `waves = {amp: 2.5, periode: 10, speed: 0.2}` - the wrapper math is
  right; shader path active, no fallback Image.
- Phase rate measured against the scene clock: **0.00200 rad/ms = 2.0 rad/s**,
  exactly `(t/CYCLE_MS)*speed`.
- Rendered pixels genuinely change frame to frame (the ripple animates).
- `emulator` (amp 0) correctly falls back to a plain Image, no shader.
- `gods` screenshot: the sunken sailing ship renders upright and undistorted -
  i.e. no y-flip or UV error from the extraction/shader.
- e2e 7/7; `tsc -b` clean.

Two things worth remembering, both found by testing rather than reasoning:

- **Don't `textures.remove()` the extracted canvas in `destroy()`.** Removing it
  during the scene's SHUTDOWN (while the renderer still holds it) silently
  **wedges the scene transition** - the level never leaves. The key is shared
  (`"wavy-bg"`) instead: only one background is ever alive at a time, and
  `extractTexture()` replaces it, so at most one texture lingers - verified
  capped at 1 across level changes.
- Launching headless Chromium with `--use-gl=angle --use-angle=swiftshader`
  makes this hang; plain headless already reports `renderer.type === 2` (WebGL).
