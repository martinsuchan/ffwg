# 027 - World Map

2026-07-10

## Context

The port booted straight into one hardcoded level (`main.ts`'s `LEVEL_NAME`).
The user asked for the real hub screen: a World Map shown at startup,
listing every level, from which a level launches and to which the player
returns afterward - not just a convenience picker, the actual original
mechanism. Requirements: **sandbox mode** (every node, including normally-
hidden secret branches, shown and clickable regardless of real
progression - solved/unsolved coloring still reflects genuine
`localStorage` data), clicking an already-solved level must show the
original's **Pedometer** screen (Run again / Replay solution / Cancel),
and the map's 4 large corner buttons (Intro/Exit/Credits/Options) were
explicitly scoped as analysis-now-build-later.

## Research: how the original works

Read the actual source before designing anything (`legacy/src/menu/
WorldMap.cpp`, `LevelNode.cpp`, `NodeDrawer.cpp`, `WorldBranch.cpp`,
`Pedometer.cpp`, `SolverDrawer.cpp`, `WorldInput.cpp`, plus the state-
machine base in `legacy/src/plan/`):

- **Rendering**: one static, non-scrolling 640x480 background
  (`images/menu/map.png`) - no camera/pan/zoom. Level nodes are drawn on
  top from graph data, not baked into the art: every node always shows a
  dim "far" icon (`n_far.png`) as a base layer, `OPEN` nodes get an
  animated 4-frame pulse overlay (`n1`-`n4.png`), `SOLVED` nodes get a
  static gold overlay (`n0.png`). `HIDDEN` nodes are skipped entirely.
  Edges are thin lines between non-hidden parent/child pairs. Hover is a
  13px-radius circular hit test (only `>= OPEN` nodes are hoverable at
  all), showing a translucent ring plus the level's display name as a
  bottom-center label.
- **Graph data**: `legacy/script/worldmap.lua` - 80 unique
  `branch_addNode(parent, codename, datafile, x, y, hidden=false,
  poster="")` calls (root `"start"`, parent `""`) plus one
  `branch_setEnding(...)` (no x/y at all - the original never draws or
  clicks it directly either; it auto-triggers once every other node is
  solved, out of scope here, so this port doesn't render it as a node).
  Names come from `legacy/script/worlddesc.lua`
  (`worldmap_addDesc(codename, lang, name, desc)`); best-known-solution
  move counts from `legacy/script/worldfame.lua`
  (`node_bestSolution(codename, moves, author)`).
- **Node state model**: `HIDDEN | FAR | OPEN | SOLVED`, purely *derived*
  (never an explicit "unlocked" flag) - solved iff `solved/<codename>.lua`
  exists, `OPEN` reached by a solved parent promoting its children. This
  port already had the exact solved-check equivalent
  (`loadSolvedMoves(codename) !== null`, docs/026) - just needed a new
  pure derivation function over the graph, not new persistence.
- **World Map <-> Level transition**: the original does a *push/pop* with
  the lower state merely paused, not destroyed - `WorldMap` is a session-
  long singleton created once at boot; a level launch is `pushState`;
  leaving (Escape, or an automatic ~10-round celebration after solving)
  is a plain `pop` back to the still-alive map, which reacts via one
  `own_resumeState()` hook marking the just-played node solved.
- **Pedometer**: appears only for a `SOLVED` node - level name, an
  odometer panel, the saved solution's move count (original: a per-digit
  "slot machine" roll-in), a "your solution vs. best known" comparison
  line, and 3 buttons (Run/Replay/Cancel).
- **4 corner buttons**: 100% image+pixel-mask driven (per-pixel color
  sampling against `map_mask.png`), not the engine's real `WiButton`
  widget at all - labels are baked into the map art. Intro plays a movie/
  attract-mode demo; Exit quits the whole native process (`WorldMap` is
  the state-stack root, so popping it empties the stack); Credits scrolls
  a static poster image; Options pushes a full settings screen (sound/
  music volume, language, subtitles) this port has no equivalent of at
  all yet.

## Design decisions (all confirmed with the user first)

**No push/pop-with-pause needed.** Because all persistent state (which
levels are solved) already lives in `localStorage`, not scene objects,
the map can be recomputed **fresh from storage every time it's shown** -
simpler and correctness-equivalent to the original's incremental single-
node update. This port keeps using its own already-proven `scene.start()`
pattern (full teardown/recreate, docs/025) for both directions instead of
adopting Phaser's `launch`/`sleep`/`wake` - `WorldMapScene.create()`
always re-derives every node's state from scratch, no "which node did I
just come from" signaling needed at all.

**Sandbox mode**: every node, including the 10 hidden secret branches, is
forced `open` unless already solved (`SANDBOX_MODE = true`,
`web/src/game/worldMapState.ts`) - but the *real* graph derivation (parent-
solved cascade, hidden-branch reveal) is fully implemented, not stubbed,
so flipping the flag off later restores real progression-gating with zero
other changes.

**Corner buttons stay inert this pass** - the original `map.png` renders
as-is (its labels are baked into the art either way), but no click
handlers exist for the 4 corners. None of their real destinations exist
in this port yet (movie/attract-mode harness, a from-scratch settings
screen, a poster-scroll screen, and Exit doesn't translate to a browser
tab as-is) - explicitly a follow-up, not built now.

**Map language is Czech** (`MAP_LANG = "cs"`, `worldMapLoader.ts`),
matching the in-level dialog/voice default from docs/018, per the user's
choice for whole-game consistency over English UI chrome (general button/
status text stays English throughout, matching every other scene - the
Czech choice was specifically about the map's *level names*, confirmed
against `worlddesc.lua` having a real `"cs"` entry per level).

## What was built

- **`web/src/lua/worldMapLoader.ts`** (new): one-shot (non-persistent,
  like `levelLoader.ts`, not `levelScript.ts`'s live-engine pattern)
  wasmoon parse of `worldmap.lua` + its two `file_include`d files, host
  bindings for `branch_addNode`/`branch_setEnding`/`worldmap_addDesc`/
  `node_bestSolution` collecting into a plain `WorldMapData` (nodes,
  names, best solutions) - `datafile`/`poster` args are dropped, since
  `loadLevelModels()` already assumes the `script/<codename>/` convention
  directly and posters are out of scope.
- **`web/src/game/worldMapState.ts`** (new): `computeNodeStates(data,
  solved, sandboxMode)` - a pure function, not the original's in-place
  tree mutation (`LevelNode::setState()`/`addChild()`'s promotion
  cascade) - recomputed fresh every call instead.
- **`web/src/scenes/WorldMapScene.ts`** (new): the map screen - node
  icons/edges/hover/selection, a shared scene-level pulse timer driving
  every open node's idle animation in sync (matching the original's own
  shared `TimerAgent::getCycles()`-driven approach, reimplemented as a
  plain 6-step ping-pong instead of the original's hand-rolled branching -
  same visual effect), click-to-launch (`loadLevelModels()` then
  `scene.start("level", {levelData})`, with a loading toast and a double-
  click guard), and `this.scale.setGameSize(640, 480)` on entry (the map
  is fixed-size; each level has its own room size - `LevelScene.create()`
  now does the matching `setGameSize(roomWidth*GRID_SCALE, ...)` for
  itself, since previously the canvas was sized once at boot and never
  changed).
- **`web/src/scenes/PedometerUI.ts`** (new): an in-scene overlay (not a
  separate Phaser scene - lighter weight, owned by `WorldMapScene`) -
  panel art at the original's exact position (193,141) and its 3 buttons
  at the original's exact relative positions (86/128/170,100), replacing
  per-pixel mask hit-testing with plain interactive text buttons. Move
  count uses a simple tween count-up instead of the original's per-digit
  slot-machine sprite animation - a deliberate simplification, same
  spirit as this project's other presentation simplifications (e.g.
  docs/011's plain fade instead of a pixel-dissolve shader). Run and
  Replay both do the same `loadLevelModels()` -> `scene.start(...)` dance
  as a normal node click.
- **`web/src/scenes/LevelScene.ts`**: dropped its constructor-injected
  `levelData` in favor of `init(data: {levelData})` (exact mirror of
  `ReplayScene`'s existing pattern - level data is chosen at runtime by
  the map now, not known at boot); new `keydown-ESC` -> `scene.start(
  "worldmap")`; canvas resize on entry (above).
- **`web/src/scenes/ReplayScene.ts`**: gained `returnTo: "level" |
  "worldmap"` (via `init()`), since where Escape goes back to now
  genuinely depends on how replay was launched - a real distinction the
  original also has (P from a live level vs. the map's Pedometer "Replay"
  button are different entry points there too). `LevelScene.launchReplay()`
  (P) defaults to `"level"`; `PedometerUI`'s Replay button passes
  `"worldmap"`.
- **`web/src/main.ts`**: boots into `WorldMapScene` (awaiting
  `loadWorldMap()` first, same "load before constructing the Game" shape
  the old hardcoded-level boot already had) instead of one fixed level;
  `LevelScene`/`ReplayScene` are now registered by class, not a pre-built
  instance, so Phaser constructs them fresh per launch.
- **Asset conversion**: ran `scripts/convert-assets.ps1 -Level menu`
  (menu art had never been converted at all) and then the **full,
  unfiltered batch** for every level's images/music/sound - previously
  only a small verification set (`airplane`, `viking1`, shared pool) had
  ever been converted (docs/018); with the map now making all ~80 levels
  actually reachable and clickable, most would otherwise show as blank/
  broken (missing textures) despite the physics/game logic working fine.
  This was necessary for "all levels available" to mean something real,
  not just architecturally.

## Bugs found and fixed during verification

- **World-map node hover/click never fired**: `far.setInteractive({
  hitArea: new Phaser.Geom.Circle(0, 0, NODE_HIT_RADIUS), ... })` used a
  circle centered at local `(0,0)` - but Phaser hit-areas are in texture-
  local space (`(0,0)` = the frame's top-left corner), not centered on the
  object's origin point, so only the icon's top-left quadrant ever
  registered a hit. Fixed: `new Phaser.Geom.Circle(far.width / 2,
  far.height / 2, NODE_HIT_RADIUS)`. Found via direct pointer-position
  inspection (`scene.input.activePointer`) showing the pointer correctly
  landing on the node while `pointerover` still never fired - confirmed
  it was a hit-area geometry bug, not an input/coordinate-mapping issue.
- **Pulse-timer crash on scene transition**: `WorldMapScene`'s open-node
  pulse `TimerEvent` could fire one more time after `scene.start()`
  transitioned away (`this.pulseTimer?.remove()` in a `SHUTDOWN` listener
  wasn't enough to prevent an already-queued tick), calling `.setTexture()`
  on an already-destroyed `Image` and throwing uncaught. Fixed with a
  defensive `if (overlay.scene) overlay.setTexture(key)` guard in
  `advancePulse()`.
- **`fetchSoundDurations()` uncaught `JSON.parse` crash** (pre-existing,
  not introduced this pass, but only ever exercised by `airplane`/
  `viking1` before): Vite's dev server SPA-fallback-serves `index.html`
  (200 OK, not a real 404) for any unconverted level's missing
  `sprite.json`, so the existing `try { fetchText(...) } catch { return;
  }` guard never triggered - `JSON.parse` on the returned HTML was
  outside that try block and threw uncaught. Now the full fetch+parse is
  one try/catch, matching the function's own stated intent ("tolerant of
  404s"). Was invisible before this pass because no level besides
  airplane/viking1 had ever actually been launched in the browser.
- **`windoze`'s unsupported `fish_extra` kind left the game in a stuck,
  unrecoverable state**: `GameEngine`/`ModelFactory` throwing on an
  unknown model kind (correct, existing "fail loud" behavior, docs/024)
  happens *synchronously inside `LevelScene.create()`* - a different
  failure point than the async `loadLevelModels()` step `WorldMapScene`
  already guards. Left uncaught, this stopped `create()` mid-way with
  Phaser considering the scene never properly started: neither the map
  nor the level ended up active, unrecoverable without a full page
  reload. Fixed by wrapping `LevelScene.startEngine()`'s call in `create()`
  with try/catch - on failure, shows an error message with an "Esc for
  the map" hint (the Esc handler is registered earlier in `create()`, so
  it still works) instead of leaving the scene half-built.

## Verification

- `npx tsc -b` clean throughout.
- Real-browser (Playwright, `window.__game` debug hook temporarily added
  and removed after, same technique as every prior phase): map renders
  all 80 nodes with real art (screenshot-verified against the original's
  actual underwater-world illustration, corner labels intact), hover
  shows the correct Czech name + selection ring, clicking an unsolved
  node loads and plays it, canvas resizes from 640x480 to the level's own
  room size and back on Escape, Escape returns to the map correctly.
- Solved `airplane` via the existing headless `engine.loadMove()` path
  (same reliable technique as docs/026's verification) inside a real
  `LevelScene`, let the live round loop detect `isSolved()` for real:
  `ffwg:solved:airplane` written, node renders solved on return, clicking
  it shows the Pedometer with the correct move count (verified against
  the count-up tween's final value) and Czech level name.
- Pedometer Run launches interactively from scratch (fresh, empty move
  string); Replay launches `ReplayScene` with the saved solution and
  `returnTo: "worldmap"` (Escape confirmed landing back on the map, not a
  level); Cancel dismisses the overlay, map stays interactive. Regression:
  P-triggered replay from an actively-playing level still has `returnTo:
  "level"` and Escape correctly returns to that same level.
  `windoze` fails gracefully with an on-screen error + Esc-to-map, map
  stays fully usable afterward for other nodes.
- Full asset-conversion spot check: `start` (never previously converted
  or browser-tested at all this project) now renders its real background/
  furniture/fish art with zero missing-asset warnings, confirming the
  full-batch conversion actually took effect end-to-end, not just for the
  couple of levels this project had exercised before.

## Open for next time

- The 4 corner buttons remain unwired (Intro attract-mode/movie, Exit's
  browser-tab-appropriate reinterpretation, Credits poster-scroll,
  Options - this port's first real settings screen) - a real follow-up
  task, not started.
- Sandbox mode (`SANDBOX_MODE` in `worldMapState.ts`) is a single
  top-level boolean - flipping it off restores real progression-gating,
  not yet asked for.
- No "last played level" memory or auto-resume - the map always starts
  fresh at boot (matches the roadmap's own earlier note that this needs a
  level-select UI to mean anything, which now exists).
- `worldfame.lua`'s best-solution comparison text is wired up but not
  deeply verified against every level's real recorded author/move-count
  data - only spot-checked structurally.
- The ending node (`branch_setEnding`) is parsed but intentionally never
  rendered/reachable, matching the original's own "auto-triggers once
  everything else is solved" behavior being out of scope for sandbox mode.
