# 002 — Test project

2026-08-14

Turns the correctness argument from docs/001 into `dotnet test`: an MSTest
project at `solver/tests/FishFillets.Physics.Tests`, 101 tests, ~120 ms.

```
> dotnet test
Passed!  - Failed: 0, Passed: 101, Skipped: 0, Total: 101, Duration: 120 ms
```

`scripts\build-solver.ps1` runs it now instead of shelling out to
`ffsolve verify --all`. (With `-Publish` it *also* still runs `verify --all`
against the published binary — the suite exercises the managed build, so that
step is what proves the AOT executable itself works.)

## What's tested

**`ReferenceSolutionTests` — the corpus, one case per level.** The same 80
recorded solutions docs/001 verified, but as individual test cases, so a failure
names the level instead of a count. Levels come from
`Corpus.LevelsWithSolutions()`, which is also what excludes `ending` (a level
with no recorded solution) and `redhat` (a solution with no level content in this
repo) by construction rather than by a hardcoded skip list.

`Corpus_CoversEveryLevelThatHasASolution` asserts that list has exactly 80
entries. Without it a missing or truncated `solver/levels` export would silently
reduce the theory to zero cases — a green run proving nothing. It needs updating
if level content ever changes, and that is the point.

**`InvalidSolutionTests` — that wrong answers are actually caught.** A validator
which accepts every real solution is worthless if it also accepts bad ones, and a
search leans on exactly this: `ApplyMove` returning false is how an illegal
successor gets discarded, and `IsSolved` is the goal test.

Three distinct kinds of bad, each checked to fail *at the right place*:

- *Rejected outright* — an unknown symbol; a legal symbol whose move is blocked;
  a move appended after the fish has already escaped (its symbols stop driving
  once `willMove()` is false).
- *Legal but not a win* — the empty string; a solution one move short.
  `SolutionIsNotSolvedBeforeItsLastMove` generalises this: replay four levels
  move by move and require `IsSolved()` to be false at every step but the last.
  That catches an `IsSolved` firing too eagerly, which would make a search return
  truncated "solutions".
- *Rejection is non-destructive* — a rejected move must leave the room byte-
  identical, or a search would corrupt its own state just by probing a successor
  that turns out illegal. Checked at every step along a real solution for an
  unknown symbol, and at the blocking point for a genuinely blocked one.

The snapshot those last two compare deliberately excludes `TouchDir`, because
`SetTouched()` records it even on a rejected move — the caveat docs/001 §3 raised
about keeping it out of a search's state key, now pinned down by a test.

**`SyntheticRuleTests` — hand-built rooms, one rule each.** The corpus proves the
rules compose, but only along paths that *work*: it never visits a losing state,
which is where a search will spend most of its time. These cover push/no-push by
power, turn-instead-of-move, load-time settling, automatic escape at the border,
and death by stress — in 7×6 rooms small enough to check by hand.

Two are deliberately paired so each measures what it claims:
`HeavyItemRestingOnSmallFish_KillsIt` (and `IsSolvable()` goes false — a search's
primary prune) against `HeavyItemRestingOnBigFish_IsSurvivable`, which differ
only in the fish's power.

## Verifying the tests discriminate

A suite is worth what it catches, so both families were checked against
deliberate mutations of the engine:

| mutation                                          | failures                                  |
| ------------------------------------------------- | ----------------------------------------- |
| `GoLeft` ignores facing (turn-then-move collapses) | **82** — corpus-wide                       |
| `ApplyMove` accepts moves no unit owns             | **6** — only the rejection tests; corpus green |

The second is the interesting one: a lax validator doesn't break *valid*
solutions, so the corpus alone would never have noticed it. That is precisely the
gap `InvalidSolutionTests` exists to close, and the two families are
complementary rather than overlapping.

## Also changed

`Paths` and `SolutionFile` moved out of the CLI into `FishFillets.Physics` as one
`Corpus` class, since the tests need the same repo-root discovery and
`saved_moves` parsing. It sits beside `LevelLoader`, which already reads levels
off disk. `Corpus` is an instance now rather than the CLI's static mutable state,
so tests can resolve it once and share it safely.

## Open

- No unit-test coverage of `ResistArena`'s LIFO discipline in isolation; it is
  exercised heavily but indirectly by everything else.
- Differential fuzzing against the TS engine (docs/001 §7) is still the missing
  piece for dead-end states — the synthetic tests cover a hand-picked few, not a
  systematic sweep.
- Tests run against the Debug/managed build. The AOT binary is only smoke-tested
  via `verify --all`; if AOT ever diverges from JIT, only that would catch it.
