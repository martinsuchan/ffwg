# 018 — Fixing the review's correctness findings (C1-C7)

The code review's correctness findings, fixed against the regression suite
(docs/015, docs/017): each one had a test that was red before and is green now.

| id | finding | fix | pinned by |
|---|---|---|---|
| C1 | `NoWayOut`'s per-layout cache ignored which fish are still in play, so a verdict computed after the big fish left was reused while it was still there (and the reverse) | the layout key carries each unit's alive/out/lost flags (`Solver.WriteLayout`) | `WhiteBoxTests.StuckCache_*`; `Stuck` property now drives the real, cached `NoWayOut` |
| C2 | `MacroSolver`/`ItemSolver` swept f-buckets forwards, losing every child whose f fell below the sweep (all of weight > 1, and weight 1 under an inconsistent h) | the open list is one shared `BucketQueue`, lifted from `Solver` | matrix columns `macro-w2`, `items-w2` on every level |
| C3 | item exit distance charged a turn, overestimating by one | items get a facing-free BFS (`RelaxedDistance.ToExit`, `freeFall`) | `Heuristic_IsAdmissible`/`IsConsistent` on `goal-out-push-right` |
| C4 | `--work` measured goal_alive fish to the exits; with no exit the start's guide was "unreachable" and the open list tried to allocate ~536 M buckets | only fish that must leave are measured; the guide is `max(admissible, toll)`; a start guide of unreachable returns "unsolvable"; `BucketQueue` rejects absurd priorities | matrix `goal-out-drop-hole / work-3` (was marked hazardous, never run) |
| C5 | the window optimiser measured a fish that is out in the target to its parked (-1000,-1000), so windows ending after an escape were never searched | an out-in-target fish is measured to the nearest exit (walls-only BFS) | `Window_RemovesTheDetour` on `exit-detour` |
| C6 | a wrongly frozen model moving would corrupt the search's room silently | `LevelReduction.ThrowIfFrozenMoved` after every applied move in all three searches | `WhiteBoxTests.WrongReduction_FailsLoudly_C6` |
| C7 | `NoWayOut` demanded a way out of every living fish, condemning goal_alive levels from the start | only units whose goal is to leave are checked | matrix `goal-out-drop-hole / astar-stuck`, `Stuck` property |

## Effects

- **No effort change where nothing was wrong.** Every pre-existing baseline cell is
  identical except two, both explained: `goal-out-push-right / work-3` 47 -> 11
  expansions (C4: the toll no longer steers a goal_alive fish at the exit) and
  `heavy-gate / astar-stuck` 612 -> 594 (C1 cut both ways - a stale "can leave"
  had kept truly dead states alive too). The six corpus golden counts and every
  physics digest are unchanged.
- **Speed:** `ffsolve bench --suite` vs before: 0.96-1.01x, within run-to-run
  noise - the C6 guard and the wider layout key cost nothing measurable.
- **Fuzzing:** 5,240 usable rooms (seed 11) with no finding at all, where the same
  rooms previously produced C3/C7 violations in hundreds.
- **Still open, by design:** `MACRO-PARK` (heavy-gate's macro columns) - the macro
  decomposition cannot express "step aside so the other fish can push". That is a
  completeness limit of the method (docs/005, docs/008), not a bug; it stays in the
  KnownBug run as a ratchet.

## Notes

- C6's guard only sees moves. A wrong freeze that makes a level look unsolvable
  before any move (freezing heavy-gate's plug walls the small fish in for the
  heuristic) still returns "unsolvable" quietly; that verdict rests on the
  reduction itself, checked by `LevelReduction.Verified` and the reduction
  property test.
- With every finding fixed, the fuzzer attributes nothing any more; the
  mechanism stays (`MicroVariant.KnownBug`, `Violation.Cause`) for the next open bug.
- `Solver.Solve` now clears its visited set, queue and node array first, so a
  `Solver` can be reused (`bench --suite` used to rely on a fresh one per run).
